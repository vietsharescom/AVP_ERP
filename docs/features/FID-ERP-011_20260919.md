## 4. CONTRACT

### 4a. `POST /api/auth/login`
Input:
```json
{ "station": "FACTORY", "password": "..." }
```
`station` ∈ `{"OFFICE", "FACTORY", "ADMIN"}` (khớp đúng giá trị
`sourceStation` đã dùng xuyên suốt dự án — không tạo thêm 1 bộ mã khác).

Output (thành công): `Set-Cookie: avp_station=<token>; HttpOnly;
SameSite=Strict` (KHÔNG `Secure` — LAN nội bộ HTTP thuần, không HTTPS,
xem `SOFTWARE_ARCHITECTURE.md` §2.2) + `{ "ok": true, "station": "FACTORY" }`.
Sai mật khẩu → 401, KHÔNG tiết lộ trạm nào tồn tại (thông báo chung
"Sai trạm hoặc mật khẩu").

### 4b. `POST /api/auth/logout` — xoá cookie, không cần input.

### 4c. Middleware — chặn route theo bảng phân quyền
```
Chưa đăng nhập (không có cookie hợp lệ) → redirect `/login` (page) hoặc
401 (API).

STATION_ROUTES (đã xác nhận 2026-09-19 — Admin KHÔNG bao gồm
/factory,/wrapping — chỉ xem/báo cáo, không tự nhập liệu Xưởng):
  OFFICE:  /capture, /lot, /packing, /reports, /search (page+API tương ứng)
  FACTORY: /factory, /wrapping, /search
  ADMIN:   /capture, /lot, /packing, /reports, /search (= ĐÚNG BẰNG bộ
           quyền Office, KHÔNG thêm /factory hay /wrapping)

Truy cập route KHÔNG thuộc trạm mình → 403 (API) / trang "Không có
quyền" (page) — KHÔNG redirect âm thầm về `/login` (dễ hiểu nhầm là
chưa đăng nhập).
```

### 4d. Sửa `sourceStation` — đọc từ session, không nhận từ client
```
capture/confirm (destination="warehouse"): BỎ field `sourceStation` khỏi
request body — server tự lấy từ session (`OFFICE` hoặc `ADMIN`, đã được
middleware đảm bảo chỉ 2 trạm này vào được route). Client KHÔNG cần gửi
field này nữa (khác hợp đồng cũ FID-ERP-002 — xem MUST NOT).

packing/confirm: SHIP ghi `sourceStation` = session hiện tại (`OFFICE`
hoặc `ADMIN`) thay vì hardcode `"OFFICE"`.
```

## 5. RULES
MUST:
  - Mật khẩu từng trạm lưu trong `.env` (`STATION_OFFICE_PASSWORD`/
    `STATION_FACTORY_PASSWORD`/`STATION_ADMIN_PASSWORD`) — KHÔNG lưu
    trong bảng DB (không cần bảng `users` ở FID này, đúng quyết định
    "theo trạm" ở WHY).
  - Cookie `HttpOnly` + `SameSite=Strict` — chặn JS phía client đọc được
    (giảm rủi ro XSS đánh cắp session), dù mạng LAN nội bộ rủi ro thấp.
  - Middleware chạy TRƯỚC MỌI route (page lẫn API) trừ `/login`,
    `/api/auth/login`, tài nguyên tĩnh (`_next/*`).
  - `sourceStation` ghi vào `stock_moves` PHẢI lấy từ session — route
    nào còn nhận trực tiếp từ body client (`capture/confirm`) phải sửa
    lại (xem 4d).
  - Middleware 403 rõ ràng khi sai trạm — không redirect âm thầm (xem 4c).
  - Session hết hạn sau khoảng thời gian hợp lý (vd cuối ca — để dành
    Andy xác nhận thời lượng cụ thể, tạm 12 giờ, xem Mục 8).
MUST NOT:
  - Không đổi `checkedBy`/`operatorCode`/`confirmedBy`/`updatedBy` ở bất
    kỳ route nào đã DONE — các field này vẫn TEXT tự do, không gắn với
    session (2 lớp độc lập, xem WHY điểm 2).
  - Không cho `capture/confirm` nhận `sourceStation` từ body nữa (đã có
    session, client gửi lên chỉ để lừa/gây nhiễu — bỏ hẳn field, không
    chỉ validate).
  - Không lưu mật khẩu trạm dạng plaintext trong code/commit — chỉ
    trong `.env` (đã gitignore, đúng pattern `GEMINI_API_KEY` hiện có).


## 10. THỰC HIỆN (2026-09-19, sau khi APPROVED) — ghi chú lệch so với kế hoạch

- **`webapp/middleware.ts` → `webapp/proxy.ts`** (khác Mục 3/9 bản đầu):
  Next.js 16 đổi tên "Middleware" thành **"Proxy"** — file quy ước đổi
  thành `proxy.ts`, hàm export đổi tên thành `proxy` (không phải
  `middleware`). Đây đúng loại thay đổi AGENTS.md của `webapp/` đã cảnh
  báo ("This version has breaking changes... Read the relevant guide in
  node_modules/next/dist/docs/") — phát hiện qua cảnh báo build
  `"middleware" file convention is deprecated`, không phải đoán trước.
  Đổi tên KHÔNG ảnh hưởng logic (`isStationAllowed`/`isPublicPath` vẫn ở
  `lib/auth.ts`, tách riêng để test được).
- **Proxy mặc định Node.js runtime (Next.js 16)** — khác Middleware cũ
  (mặc định Edge runtime, không dùng được module `crypto` của Node).
  Nhờ đổi sang `proxy.ts`, `lib/auth.ts` dùng thẳng `crypto.createHmac`/
  `timingSafeEqual` mà KHÔNG cần đổi sang Web Crypto API — build hết cảnh
  báo "Node.js module... not supported in Edge Runtime" sau khi đổi tên
  file (đã xác nhận lại bằng `npm run build`, không còn cảnh báo nào).
- Middleware/Proxy KHÔNG gọi được trực tiếp trong Vitest (chỉ Next.js
  server thật mới chạy) — Mục 7 TEST CRITERIA về chặn route/redirect
  được phủ bằng cách: (1) test THUẦN LOGIC quyết định
  (`isStationAllowed`/`isPublicPath`/`parseSessionCookieValue` trong
  `lib/auth.ts` — đúng logic `proxy.ts` dùng để quyết định), (2) test
  route `capture/confirm`/`packing/confirm` tự kiểm tra session (defense
  in depth, không chỉ tin proxy) bằng cách gắn cookie giả lập vào
  `Request` test.
- `getStationFromRequest` đọc thẳng header `Cookie` (không dùng
  `NextRequest.cookies`) — để hàm này chạy được với CẢ `NextRequest`
  thật lẫn `Request` thuần đã cast trong test (test dựng `new
  Request(...)` rồi cast, không có `.cookies` thật).
- **Phát hiện phụ (không thuộc FID này nhưng sửa luôn vì gặp khi chạy
  test lặp lại)**: `packing.test.ts` có 1 test đếm
  `prisma.stockMove.count()` KHÔNG lọc `travelerNo` — Vitest chạy nhiều
  file test SONG SONG cùng 1 database `avp_erp_test`, đếm toàn bảng bị
  đụng độ với file test khác đang ghi cùng lúc → flaky (fail ngẫu nhiên,
  không liên quan logic FID-011). Sửa lại đếm đúng phạm vi
  `where: { travelerNo: tr }` — đã chạy lặp lại 3 lần liên tiếp xác nhận
  hết flaky.
