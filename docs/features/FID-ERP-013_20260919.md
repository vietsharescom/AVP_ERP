## 1. INTENT
Đưa dữ liệu SẢN XUẤT THẬT của AVP_AI (5 tab Google Sheets:
`RawMaterial`, `Warehouse`, `FinishGood`, `PartControl`, `PackingList`)
vào Postgres của AVP_ERP — **1 LẦN DUY NHẤT**, KHÔNG đồng bộ 2 chiều liên
tục — để AVP_ERP có đủ lịch sử/Traveler đang mở khi chính thức thay AVP_AI
(xem `docs/cl08_operation/SOFTWARE_ARCHITECTURE.md` Mục 0 + Mục 4 bước 6).

## 2. WHY
AVP_AI dùng Google Sheets làm database (1 spreadsheet, 5 tab — xem
`D:\AVP_AI\webapp\src\lib\sheets.ts` `SHEET_NAMES`), KHÔNG có ràng buộc
CHECK/FK/append-only nào — dữ liệu "bẩn" theo đúng nghĩa (giá trị trống,
placeholder lẫn vào cột định danh, cho phép sửa đè trực tiếp qua
`updateRowsWhere`). AVP_ERP dùng CHECK constraint + trigger append-only
chặt (FID-ERP-001 §5) — đổ thẳng dữ liệu cũ vào sẽ FAIL hàng loạt nếu
không quét lỗi trước. Pattern xử lý đã CHỐT từ vòng phản biện GPT+Grok lúc
thiết kế FID-ERP-001 (xem
`docs/records/Consultations/260917_Architechture/FINAL_DECISION.md` #6 +
`GROK.md` câu hỏi 6): **audit → quarantine → migrate → reconciliation**,
Owner ký xác nhận trước khi tắt AVP_AI — KHÔNG được để 1 dòng nào bị bỏ
qua mà không ghi lý do.

### 4c. Bảng MỚI `migration_quarantine` (Prisma, FID-ERP-001 v1.12 dự kiến)
```prisma
model MigrationQuarantine {
  id          Int      @id @default(autoincrement())
  sourceSheet String   @map("source_sheet")   // "RawMaterial" | "Warehouse" | "FinishGood" | "PartControl" | "PackingList"
  sourceRow   Int      @map("source_row")     // số dòng trong file CSV (1-index, đã trừ header)
  rawData     Json     @map("raw_data")       // NGUYÊN VẸN toàn bộ cột gốc của dòng lỗi
  errorCodes  String[] @map("error_codes")    // vd ["MISSING_REASON_CODE", "PART_NOT_IN_PART_CONTROL"]
  resolved    Boolean  @default(false)
  createdAt   DateTime @default(now()) @map("created_at")

  @@map("migration_quarantine")
}
```
KHÔNG append-only (Andy có thể đánh dấu `resolved=true` sau khi xử lý tay
— đây là hàng đợi công việc, không phải sổ cái sự kiện).
